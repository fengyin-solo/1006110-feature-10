# 盾构隧道掘进施工管理平台

面向盾构机台账、掘进环次、管片拼装、同步注浆、渣土外运、地表沉降监测与轴线纠偏的一体化盾构隧道施工管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `shield-tunnel-construction:entries` 这一项，或调用 `resetModule(模块)`。

## 渣土外运看板（跨模块编排）

渣土外运涉及 `muck / ring / safety` 三个模块，编排统一收在
`frontend/src/api/muck-service.ts`，看板（`views/muck`）与运输台账两个入口取同一份数据：

- **事实源唯一**：运输单是唯一事实源。掘进环次的「已消纳方量」不另存，由状态为「已消纳」的运输单
  按对应环号实时汇总（`disposedVolumeByRing`），环次页「出土方量核对清单」只回写核对状态/时间/签认号，
  环次那边读不到两个数。
- **滞留隐患同步**：滞留在场且有现场签认的车次，在安全巡检隐患台账挂一条待整改隐患（按运输单号关联）；
  解除滞留或确认消纳后按现场签认自动闭环。两边条数对不上时以运输单的现场签认记录为准核对
  （安全巡检页「按现场签认核对」），缺则补挂、旧则闭环，同一运输单重复滞留只保留一条待整改。
- **顺序裁决**：确认消纳/登记滞留的执行顺序固定为 ①改运输单 → ②同步安全隐患台账 → ③回写环次核对清单；
  三模块经 `local-store.ts` 的 `commitEntries` 一次事务落库，任一步落库失败整套撤回。
- **幂等**：同一运输单重复确认消纳/重复登记滞留只算一次（状态已终态即直接返回，不再写库）。
- **分权**：只有运输单所属车队的调度能改运输车辆、押运人员并做状态流转；其他车队与非调度岗位只读，
  越权改动当场拒绝。身份可在渣土外运页右上角切换演示。
- **存量迁移回填**（应用挂载前 `main.ts` 同步执行一次，版本号记录在 `…:meta`，幂等）：
  - 仓库生成的占位样例（`渣土外运样例1` 这类）整体替换为迁移基准数据；真实历史单据原样保留；
  - 缺消纳场所的按外运日期补齐：白班按外运日期的年内序次，在南山/北港/西岭三个定点场轮排，
    夜班顺延一场；日期缺失或轮排落空的，统一补兜底场「东桥综合消纳场」；
  - 程序补齐的场所挂「待核」，以现场签认为准；缺外运日期/班次的从「外运时段」拆出，缺车队默认盾构一队；
  - 迁移同时初始化滞留隐患台账与环次核对清单，本身也是三模块事务，失败不写版本号、整套撤回。
